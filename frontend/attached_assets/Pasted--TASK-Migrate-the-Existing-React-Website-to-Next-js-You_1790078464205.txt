# TASK: Migrate the Existing React Website to Next.js

You are an experienced Next.js developer. Your task is to **migrate the existing React website to Next.js while preserving the current UI, design, functionality, and user experience.**

## 1. Preserve the Existing UI

* **Do not redesign the website.**
* Preserve the current color scheme, typography, layouts, spacing, components, animations, and responsive behavior.
* Maintain the existing visual appearance as closely as possible.
* Do not remove, replace, or simplify existing UI components unless required for the migration.
* Preserve the current user experience across desktop, tablet, and mobile devices.

**Primary rule: The migration must not change the website's existing visual identity.**

## 2. Migrate React to Next.js

Convert the existing React application into a properly structured, production-ready Next.js application.

* Use the latest stable Next.js version available in the project environment.
* Use the App Router unless the existing architecture requires a justified alternative.
* Preserve existing React components and reuse them wherever practical.
* Convert routing to Next.js routing.
* Preserve existing functionality, state management, form handling, and API integrations.
* Maintain all existing pages and their behavior.
* Configure static assets, fonts, images, and other resources correctly for Next.js.
* Preserve existing environment variables and ensure they are handled securely.

## 3. Functionality Preservation

Before and after migration, inspect and verify:

* Navigation and routing.
* Buttons and CTAs.
* Forms and validation.
* API requests and backend integration.
* Authentication, if present.
* Animations and interactive components.
* Responsive layouts.
* Error handling and loading states.
* Any existing third-party libraries and integrations.

**Do not claim a feature is working unless you have actually verified it.**

## 4. SEO and Next.js Best Practices

Implement Next.js features where appropriate without altering the existing UI:

* Page metadata and SEO titles.
* Meta descriptions.
* Open Graph metadata.
* Proper heading structure.
* Image optimization where compatible with the existing design.
* Appropriate server-side rendering or static rendering.
* Clean, maintainable project architecture.

Do not introduce unnecessary changes that could affect the current website's appearance or functionality.

## 5. Migration Workflow

Follow this process:

### Step 1 — Analyze the Existing Project

Before making changes:

* Inspect the complete project structure.
* Identify the React entry points, routes, components, styles, assets, and dependencies.
* Understand the current state management and API architecture.
* Identify potential migration risks and compatibility issues.
* Determine which files require modification, replacement, or creation.

### Step 2 — Create a Migration Plan

Prepare a clear implementation plan covering:

* React-to-Next.js architecture changes.
* Routing migration.
* Component compatibility.
* Styling and asset handling.
* Backend and API integration.
* Environment variables.
* SEO implementation.
* Testing and validation.

Do not make major architectural changes without a clear technical reason.

### Step 3 — Execute the Migration

Implement the migration incrementally.

* Keep the existing UI intact.
* Reuse existing components and styles.
* Avoid unnecessary rewrites.
* Resolve dependency and compatibility issues properly.
* Ensure client-side functionality remains compatible with Next.js Server and Client Components.
* Add `"use client"` only where client-side features require it.
* Keep secrets and server-only environment variables secure.

### Step 4 — Verify the Result

After completing the migration:

* Run the development server.
* Run the production build.
* Check for TypeScript, ESLint, and runtime errors where applicable.
* Test every existing route.
* Verify forms, buttons, animations, and API functionality.
* Compare the migrated UI with the original React website.
* Check responsiveness across screen sizes.
* Fix any regressions before declaring the migration complete.

## 6. Restrictions

* Do not redesign the website.
* Do not change the color scheme.
* Do not remove existing features.
* Do not replace working functionality with placeholders.
* Do not delete files without understanding their purpose.
* Do not hardcode secrets or API keys.
* Do not assume that a successful build means all functionality works.
* Do not make unrelated changes to the project.

## 7. Final Report

When the migration is complete, provide:

1. Summary of the changes made.
2. Files and components modified.
3. React-to-Next.js architectural changes.
4. Features tested and verification results.
5. Any remaining issues or limitations.
6. Instructions for running the migrated Next.js application.

**Success Criteria:**

The website should run on Next.js while retaining the existing React website's UI, design, functionality, responsiveness, and user experience as closely as possible. The migration should be clean, maintainable, and production-ready.
